About

I am in my final year of Automation & Applied Informatics at the Faculty of Hydrotechnics, UTCB Bucharest — the faculty name is misleading, the programme is control systems and software. Since July 2026 I work at DeviDevs Technologies as a software engineer intern, on automation and integrations.

Most of what I build has no interface. It runs on a schedule, holds a lock, retries when an API is slow, and writes to a file that something else is also reading. That is the part I find interesting: not the feature, but what happens on the second Tuesday when two things run at the same time.

  • One writer at a time. Concurrency handled with kernel file locks (fcntl.flock) and explicit signal handlers, so an interactive session and a headless job never corrupt the same file.
  • Scheduled, not supervised. Jobs run under macOS launchd, cache with conditional HTTP requests, and are expected to fail quietly and recover rather than need a human.
  • Behaviour over structure. In game AI the state machine took an afternoon; the weeks went into making the enemy stop oscillating between two hiding spots.

Selected work

BetterTanks — enemy AI for a 2D tank game

Unity 2D · C# · academic practice at DeviDevs, May–Jul 2026

A five-state enemy tank: patrol, chase, shoot, take cover, run. The interesting part is cover selection — for every destructible wall it scores four candidate positions taken from the collider bounds, and strongly prefers the side facing away from the player. It also has to handle the wall being destroyed while it is hiding behind it.
